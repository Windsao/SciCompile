01

Abstract

Scientific papers describe reusable methods, but learning from them requires turning dispersed scientific knowledge into actions whose correctness can be checked. We introduce SciCompile, a framework that compiles papers and available data into scientific experiences connecting a task, its assumptions, tools, evidence, and executable verification. Agents practice these experiences and retain useful instructions and programs while model weights remain fixed. Scientific compilation must preserve the conditions that make a procedure valid. Our source-linked benchmark on X-ray diffraction and adsorption measures both the support for generated claims and the coverage of required knowledge, including what a fixed model can recover in a reconstructed report. Across five compilers, claim Precision is 97.63–100.00%, while knowledge Recall is 81.91–91.05%, identifying omission as a central challenge.

To address it, SciCompile-ACG binds scientific dependencies to their coverage in a draft, selects context around possible omissions, and appends source-supported information. In the reported four-model comparison, this workflow has aggregate F1 scores 2.34–12.63 points above the reported direct references without lower Precision. Separate downstream studies evaluate the original compiled-practice pipeline: GPT-6.1-Sol passes 20/23 terminal-workflow checks versus 18/23 after raw-paper learning, and GPT-6-Luna answers 52/64 scientific plot questions versus 50/64. In a separate coating-inference task, GPT-6.1-Sol passes 3/8 datasets with papers, 7/8 with ordinary compilation, and 8/8 with SciCompile-ACG. These findings establish scientific compilation as a measurable interface between literature, verifiable practice, and reusable agent skills. Project website: https://windsao.github.io/SciCompile/.

02

Method

A paper describes what worked. An experience makes the procedure explicit enough for an agent to practice it, check its outputs, and reuse what it learns.

The scientific experience

The compiler receives paper text, available data, and source provenance. All material and biological experiences in the reported studies use the complete six-component contract, serialized as structured JSON:

E = (C, Q, T, O, V, Π)
C
ContextAssumptions and conditions under which the procedure applies.
Q
QuestionThe scientific goal and the required output.
T
ToolsOperations, dependencies, and input/output formats.
O
EvidenceAvailable observations and explicitly missing inputs.
V
VerifierExecutable checks, tolerances, and scoring rules.
Π
PermissionsRestrictions on source use and derived material.

Keep methods connected to their conditions

SciCompile-ACG uses an active context graph to find scientific dependencies that a draft may have missed. A formula, for example, must stay linked to its units and range of validity.

  1. Map the source dependencies

    Link claims, methods, evidence, units, conditions, and limitations to their source locations. Relations include “requires,” “constrains,” and “qualifies.”

  2. Connect the graph to a draft

    Generate an experience and bind source nodes to its records. A controller selects up to 24 possible gaps, prioritizing critical conditions and relationships.

  3. Review and supplement

    Review the selected context with the complete draft and source. Append attributed additions within a 6,500-token final budget, preserving existing records.

The same three-stage policy is used across papers. The compiler has no access to benchmark requirements or scores and needs no per-paper meta-agent optimization.

How verification and skill learning work

The verifier runs Python checks on the agent’s intermediate or final artifacts. It returns distinct outcomes:

  • nullRequired evidence is unavailable.
  • 0The submission or a critical validity check fails.
  • 0 to 1Otherwise, a weighted sum of component scores measures correctness.

A separate model session implements a second scorer from the source and written contract. The controller compares both scorers on valid, corrupted, and missing-evidence cases before freezing the verifier.

  1. Practice. Run tools, submit artifacts, and receive verification feedback.
  2. Revise. Propose reusable instructions and programs from the execution record.
  3. Select. Keep a revision only if mean reward improves on private selection cases and no regression case worsens beyond numerical tolerance.
  4. Reuse. Freeze the accepted skills and provide them to a fresh agent on new tasks.

Learning changes the stored skills, programs, and retrieval catalog. Model weights, tools, and the base harness remain fixed.

Memory compilation protocol

All methods receive the same source packets, figures, task scope, and output schema, with a 6,500-token final-artifact limit. Direct compilation generates a tuple in one stage; ACG uses three stages.

A-MEM links source notes and updates retrieval context. MAGMA retrieves through semantic, entity, scientific-dependency, and source-supported temporal relations. Each adaptation uses five logical generation stages, a fixed MiniLM encoder, six source-based review queries, and a 3,000-token retrieved-memory limit. Both retrieve evidence to supplement a direct draft with bounded additions.

All three memory workflows achieve higher F1 than direct compilation within each model block. SciCompile-ACG has the highest F1 across all four models. For the open models, ACG achieves higher Recall while A-MEM and MAGMA have higher Precision; ACG’s F1 exceeds the strongest memory alternative by 1.30 points for Qwen and 2.44 for Mistral. The comparison summarizes complete workflows across output batches. The direct rows are memory-comparison references, separate from the five-model fidelity experiment, and are not a common paired control for every adapter.

A separate GPT-6.1-Sol evaluator scores frozen outputs. Both compiler tables use the same aggregate F1: 2 × P × R / (P + R), calculated from each row’s displayed Precision and Recall and rounded to two decimals. P and R retain the reported condition aggregates. Where output-level records are available, P and R are averaged within each paper and then equally across papers. Aggregate F1 differs from the mean of output-level F1 scores. See the paper’s compiler evaluation and memory compilation protocols for the annotation and retry rules.

SEM execution and repeated-run results

SEM requires instance masks and crystal classes. PQ averages the class-aware score across two final images. Four annotated training images and up to three aggregate practice checks on one practice image support development.

The repeated comparison uses the same 20-minute authoring budget in all three conditions. A controller retains the best practice-scoring source version, executes it on final inputs, and requires an independent replay to reproduce the predictions. ACG additionally connects source records to execution checks for scope, foreground, boundaries, features, validation, and output identity.

Across three runs, mean PQ and sample standard deviation are 0.108 ± 0.052 for raw papers, 0.124 ± 0.064 for ordinary compilation, and 0.142 ± 0.068 for ACG with execution checks. All nine submissions are valid. This development comparison follows analysis of the same task. The original single-run protocol yielded 0.3488 for raw papers, a protocol zero for ordinary compilation, and 0.0814 for ACG. Appendix J of the paper describes both protocols.
